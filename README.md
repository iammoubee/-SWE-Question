# Software Engineering Assignment (OBE-Aligned)

## Course & Assessment Metadata

* **Course Title:** Software Engineering — Software Design
* **Assessment Type:** Individual Assignment
* **Total Marks:** 40 Marks
* **Allocated Time:** 1 Hour (60 Minutes)
* **Domain:** Cognitive Domain (Bloom's Taxonomy)
* **Target Bloom's Levels:** Knowledge (C1 / Remembering) & Understanding (C2 / Comprehending)
* **Qualification Standard:** Bangladesh National Qualifications Framework (BNQF) — Higher Education Sub-Sector, **BNQF Level 7 (Bachelor's Degree)** alignment (knowledge and understanding of core discipline concepts, principles, processes, and structures)

## Question Paper (40 Marks — 1 Hour)

### Instructions for Students
1. Answer **all** questions in the space provided or on your answer sheet.
2. Time allocation is **1 hour (60 minutes)**. Manage your time according to the marks assigned to each sub-question.
3. Be concise, accurate, and directly address the required cognitive level (**State/Define/List/Identify** for Knowledge; **Explain/Compare/Distinguish/Interpret** for Understanding).

---

### Question 1: Design Fundamentals & Quality Metrics [14 Marks]

* **(a) [4 Marks] — CO1 | Bloom: Knowledge (C1)**
  State the two basic steps of the software design process and identify the key artifact (including rationale) produced as the outcome of the design process.

* **(b) [5 Marks] — CO1 | Bloom: Understanding (C2)**
  Explain why **high cohesion** and **low coupling** are desirable in modular software design, and briefly distinguish between *data coupling* and *control coupling* (or *functional cohesion* and *coincidental cohesion*).

* **(c) [5 Marks] — CO2 | Bloom: Understanding (C2)**
  Explain what **LCOM2** (or **LCOM3**) measures in an object-oriented class, state what a lower metric value generally indicates about class cohesion, and explain in plain terms why an **LCOM3** value greater than `1` points to a potential issue in a class.

---

### Question 2: Software Architecture & Design Patterns [18 Marks]

* **(a) [4 Marks] — CO3 | Bloom: Knowledge (C1)**
  List any **four** software architectural styles covered in class (e.g., Layered, Event-Based, MVC, Blackboard/Repository, Pipes and Filters) and identify the primary structural elements or data-flow mechanism of each.

* **(b) [5 Marks] — CO3 | Bloom: Understanding (C2)**
  Explain how the **Event-Based** architectural style differs from the **Pipes and Filters** architectural style in terms of how components communicate and process data.

* **(c) [5 Marks] — CO4 | Bloom: Understanding (C2)**
  Compare the **Strategy** pattern and the **Template Method** pattern: explain how each structures algorithmic variation and state one key benefit or liability of each pattern.

* **(d) [4 Marks] — CO4 | Bloom: Understanding (C2)**
  Explain the difference between **Single Table Inheritance** and **Class Table Inheritance** when mapping an inheritance hierarchy to a relational database, including one trade-off of each approach.

---

### Question 3: User Interface Design [8 Marks]

* **(a) [4 Marks] — CO5 | Bloom: Knowledge (C1)**
  List **four** fundamental UI design principles (e.g., learnability, user familiarity, consistency, minimal surprise, recoverability, user guidance, user diversity) and **two** UI interaction modalities.

* **(b) [4 Marks] — CO5 | Bloom: Understanding (C2)**
  Explain how to present information in a UI so that it remains clear and accessible to users with **color vision deficiencies (color blindness)**, including why relying on color alone—or green–red combinations—is discouraged.

## Grading Rubric Summary

* **Full Marks (80–100% of item weight):** Accurate definitions/terminology (for C1) or clear, logical explanations with accurate comparisons and trade-offs (for C2) aligned with software design concepts.
* **Partial Marks (40–79% of item weight):** Mostly accurate core idea with incomplete explanation, minor terminology slip, or missing comparison/trade-off detail.
* **Minimal / Zero Marks (0–39% of item weight):** Vague statements, off-topic answers, or incorrect conceptual mapping.
